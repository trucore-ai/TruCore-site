1) BEFORE VS AFTER FOR GUIDE-PAGE ORIENTATION
========================================================================

BEFORE:

    Guides Overview (redundant double-label)

    "you are here" signal once inside the guide layer

    no redundant "Customer Guides Overview" — the section title IS the
    terminal crumb)
  - Individual guide breadcrumb: Documentation > Customer Guides > [Guide]
    where the "Customer Guides" segment is tinted primary-300/70 to
    signal the authenticated layer

    to a guide, the section reopens automatically
  - Active section header is highlighted with primary-300/80 color
    (was slate-500 for all sections regardless of active state)

6) AUTHENTICATED GUIDE ORIENTATION ASSESSMENT
========================================================================

Guide orientation is now complete across all discovery and navigation
surfaces:

  a) Breadcrumbs: Guide pages show a clear 3-level trail
     (Documentation > Customer Guides > [Guide]) with the Customer Guides
     segment visually distinguished via primary color tinting. Overview
     pages no longer show redundant double-labels.

  b) Sidebar active link: The active guide link shows the existing
     border-primary-400 + bg-primary-500/10 treatment. The section header
     is now tinted primary when the user is inside that section. Collapsed
     sections auto-expand when a page within them becomes active.

  c) Search: Sidebar and scored search both say "docs & guides" for
     authenticated users (unchanged from Prompt 135).

  d) Context: The guide overview page header shows "Authenticated Docs"
     label. Breadcrumbs reinforce this with the tinted Customer Guides
     segment.

  e) The full orientation chain is:
     Search → find guide → sidebar nav (section highlighted, link active)
     → breadcrumb (3-level trail with tinted guide segment) → guide content
     with "Authenticated Docs" header.

========================================================================
7) RISKS / FOLLOW-UPS
========================================================================

  - The breadcrumb overview-deduplication applies to ALL sections where
    the first item is the section's overview page. If a section's first
    item is not conceptually an overview, the collapsed breadcrumb may
    read oddly. Currently all sections with overview pages (CLI Guides,
    Customer Guides) benefit correctly.
  - Auto-expand persists to localStorage. If a user explicitly collapses
    a section while staying on a page within it, the section will
    re-expand (because the pathname hasn't changed and the useEffect
    won't re-fire). However, navigating away and back will re-expand it.
    This is the intended behavior — active sections should be visible.
  - The primary-tint on the "Customer Guides" breadcrumb segment is
    hardcoded to href="/docs/guide". If guide paths change, this check
    needs updating. A more dynamic approach could use section metadata
    but would add complexity for no current benefit.
