# First Usage Signals

> Track every external CLI run, receipt generation, and verification event.
> Each entry must map to a real interaction. No estimates, no fabrication.

---

## How to Log a Signal

1. Record what the user did (ran CLI, generated receipt, verified, etc.).
2. Note the user (handle or "anonymous").
3. Capture any observable reaction or follow-up.
4. Tag the signal strength so priority actions are clear.

---

## Signal Strength Levels

| Level | Meaning | Example |
| ----- | ------- | ------- |
| strong | User completed a meaningful action | Ran CLI, generated receipt, verified output |
| moderate | User engaged but didn't complete | Started CLI, asked how to install, visited docs |
| weak | User showed interest without action | Liked post, replied with curiosity, bookmarked |

## Action Types

| Action | Description |
| ------ | ----------- |
| cli-install | User installed `@trucore/atf` via npm/npx |
| cli-run | User ran `npx @trucore/atf trade` or similar command |
| receipt-generated | User produced a canonical receipt |
| receipt-verified | User ran `verify` on a receipt |
| docs-visited | User visited quickstart or docs pages |
| question-asked | User asked a technical question about usage |
| integration-started | User began building ATF into their system |
| bug-reported | User reported an issue (strong signal of real use) |
