TruCore early user acquisition plan (pre-control-plane expansion)

Goal:
Attract early AI-agent and bot-trading users at scale before expanding TruCore into a fuller dashboard/control plane. Prioritize real bot builders, autonomous trading agents, and developers over broad generic marketing.

Core strategy:
- Focus on proof, friction reduction, and developer adoption
- Win bot developers already executing trades
- Position TruCore ATF as policy-enforced transaction protection for AI trading agents
- Use real demos/receipts/integrations as the main growth engine
- Sequence work as:
  Foundation -> Proof -> Distribution -> Conversion -> Retention

Target users:
1. Trading bot developers
2. Agent framework builders
3. Small funds / treasury automation users / advanced bot operators
4. Autonomous infra builders (Telegram bots, Discord bots, agent runners)

Messaging:
- Lead with simple value:
  “Protect AI agent trades before execution.”
  “Enforce policy on bot actions.”
  “Generate receipts for what happened.”
- Do not lead with “control plane” yet
- Strong short positioning:
  “TruCore ATF is policy-enforced transaction protection for AI trading agents.”

Phase 1 — Foundation:
- Build one golden path:
  install -> configure -> protect a Jupiter swap -> get a receipt -> verify it
- Publish copy-paste integrations for HTTP, Python, TypeScript, OpenClaw, curl
- Default safe policy setup for new users
- Make proof page tangible with example intent / enforcement / receipt / verify flow

Phase 2 — Proof:
- Complete OpenClaw dogfooding flow
- Publicly show:
  bot intent -> ATF enforcement -> transaction result -> receipt verification
- Turn proof into:
  X post
  technical article
  docs walkthrough
  proof thread/video
- Maintain compatibility matrix for integrations

Phase 3 — Distribution:
- Focus on:
  X
  GitHub discoverability
  Solana ecosystem listings
  Jupiter/Solana dev communities
  AI agent framework communities
  Discord communities
  technical docs/articles
- Use technical, specific, provable content rather than generic thought leadership

Phase 4 — Conversion:
- Tighten site conversion ladder:
  discover -> understand -> copy snippet -> protect sample intent -> see receipt -> try own bot
- Improve:
  quickstart clarity
  supported integration visibility
  “who this is for”
  sample intent JSON
  sample receipt JSON
  setup simplicity
- Minimize painful env-var/manual config friction

Phase 5 — Retention:
- Keep early adopters through:
  reliability
  stable integration contracts
  useful receipts
  easy debugging
  fast friction removal
- Use early adopters as product-shaping feedback loop

90-day sequence:
Days 1–15:
- stabilize OpenClaw proof path
- improve quickstart
- tighten docs for Python/TS/HTTP
- improve site messaging

Days 16–30:
- publish X post
- publish technical article
- publish proof demo
- publish integration pages
- add compatibility matrix

Days 31–60:
- ecosystem submissions
- GitHub polish/topics
- targeted dev community distribution
- direct early adopter outreach

Days 61–90:
- measure drop-off
- remove setup pain
- improve policy defaults
- collect real bot use patterns
- use learnings to inform later control-plane expansion

Strategic rule:
- Do not abandon control-plane vision
- Sequence it after early users/proof/distribution
- Build the future dashboard/control-plane around real observed customer behavior
